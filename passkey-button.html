Sign-in with a Passkey Button — Progressive Enhancement

Demonstrating why a dedicated Sign-in with a passkey button should be paired with fallback forms

✅ Recommended Pattern

DO

Combine a prominent "Sign-in with a passkey" button (powered by Immediate UI mode) with a secondary password form or federated login button.

OR USE A FORM

❓ Why not just a unified "Sign in" button?

Chrome Guidance

If a single generic button queries both passwords and passkeys, Safari and Firefox will currently only display passkeys because they do not yet support Immediate UI mode and password credentials in the unified picker.

Recommendation: Always provide an explicit password form and/or federated login buttons as progressive enhancement fallbacks so all users can sign in reliably on any browser!

💻 Sign-in with a Passkey Button Code Pattern

// 1. Primary Button: Attempts immediate UI mode passkey / account picker
passkeyButton.addEventListener('click', async () => {
  try {
    const cred = await navigator.credentials.get({
      password: true,
      publicKey: { challenge: serverChallenge, rpId: 'example.com' },
      uiMode: 'immediate'
    });
    handleSuccessfulSignIn(cred);
  } catch (error) {
    if (error.name === 'NotAllowedError') {
      // 2. Progressive fallback: focus the email/password form below!
      document.getElementById('email-input').focus();
    }
  }
});
