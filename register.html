🔑 Create Discoverable Passkey (Live WebAuthn API)

Register a real WebAuthn resident passkey on localhost to test Live Immediate UI Mode in Chrome

Why register a passkey first?

In WebAuthn Immediate UI Mode (uiMode: "immediate"), Chrome checks the device's native credential store for discoverable resident keys matching localhost. If none exist, Chrome fails fast with NotAllowedError to avoid popping up an intrusive QR code dialog.

Clicking "Create Passkey" below invokes the real navigator.credentials.create() API with residentKey: "required" to register a resident passkey in your browser's platform authenticator (or Chrome DevTools Virtual Authenticator).

💻 Chrome DevTools Testing Tip

If you are testing on a Linux developer workstation or environment without a hardware biometric authenticator:

  1. Open Chrome DevTools (F12) → More Tools → WebAuthn.
  2. Check Enable virtual authenticator environment.
  3. Click New authenticator (ensure Supports resident keys is YES).
  4. Click Create Passkey on this page to store the resident key!

💻 Discoverable Credential Creation Pattern

// To make a passkey available in Immediate UI Mode, set residentKey: "required"
const credential = await navigator.credentials.create({
  publicKey: {
    challenge: serverChallenge,
    rp: { name: "Immediate UI Mode Demo Site", id: "localhost" },
    user: {
      id: new TextEncoder().encode("elisa.beckett@demogmail.com"),
      name: "elisa.beckett@demogmail.com",
      displayName: "Elisa Beckett"
    },
    pubKeyCredParams: [{ type: "public-key", alg: -7 }],
    authenticatorSelection: {
      residentKey: "required", // <-- Required for Immediate UI mode discoverability!
      userVerification: "required"
    }
  }
});
